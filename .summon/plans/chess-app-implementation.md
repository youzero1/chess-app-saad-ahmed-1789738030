# Chess App — Implementation Plan

Single-player chess (user = White, AI = Black) with full rules implemented in TypeScript, SAN move history, click-to-move UI with legal-move highlighting, check/checkmate/stalemate detection, New Game restart, and a classic wooden visual theme.

## 1. Project scaffold

1. Create `package.json` with dependencies: `react`, `react-dom`, `@tanstack/react-router`; devDependencies: `vite`, `typescript`, `@vitejs/plugin-react`, `@tanstack/router-plugin`, `tailwindcss`, `@tailwindcss/vite`, `@types/react`, `@types/react-dom`. Scripts: `dev`, `build` (tsc + vite build), `preview`.
   - Outcome: `npm install` succeeds; toolchain resolvable.
2. Create `vite.config.ts`: register `@vitejs/plugin-react`, `@tanstack/router-plugin/vite` (auto code-splitting default), `@tailwindcss/vite`; set `resolve.alias` `@` → `/src`.
   - Outcome: Vite dev server boots; `@/` imports resolve.
3. Create `tsconfig.json` (strict, `moduleResolution: "bundler"`, `jsx: "react-jsx"`, `paths` for `@/*` → `src/*`, include `src`) and `index.html` at project root mounting `<div id="root">` and loading `/src/main.tsx`.
   - Outcome: TypeScript compiles cleanly; HTML entry valid.
4. Create `src/styles/global.css` starting with exactly `@import "tailwindcss";`, followed by a `@theme` block defining the wooden palette as design tokens (e.g. `--color-wood-light`, `--color-wood-dark` for squares, `--color-wood-frame`, `--color-parchment`, `--color-ink` for panels/text) and a small base layer (page background gradient in warm brown, default text color).
   - Outcome: wooden palette available as Tailwind utilities (`bg-wood-light`, `text-ink`, etc.).
5. Create `src/main.tsx` (imports `./styles/global.css` once, builds the TanStack router from the generated route tree, renders `<RouterProvider>`) and `src/routes/__root.tsx` (minimal shell: full-height warm background, `<Outlet />`). Do NOT create or edit `src/routeTree.gen.ts` — it is generated by the router plugin.
   - Outcome: app shell renders without errors.

## 2. Chess domain types

6. Create `src/types/chess.ts`: `Color` (`"w" | "b"`), `PieceType` (`p n b r q k`), `Piece` (color + type), `Square` (0–63 index or `{file, rank}` — pick one representation, 0–63 index recommended with `file = sq % 8`, `rank = 7 - floor(sq/8)` so index 0 = a8), `Move` (from, to, piece, captured?, promotion?, flags for castle/en-passant/double-push), `GameStatus` (`"playing" | "check" | "checkmate" | "stalemate" | "draw"`), `GameState` (board array of 64, turn, castling rights, en-passant target, halfmove clock, fullmove number, move history list).
   - Outcome: single source of truth for all chess types; engine and UI import from `@/types/chess`.

## 3. Chess engine (src/lib/chess/)

7. Create `src/lib/chess/board.ts`: `initialState()` returning the standard starting `GameState`; board helpers (`squareName` like `"e4"`, `parseSquare`, `inBounds`, piece-at, king-square lookup); `applyMove(state, move)` returning a NEW immutable state (move piece, handle capture, promotion to chosen piece (default queen), castling rook relocation, en-passant pawn removal, update castling rights on king/rook move or rook capture, set/clear en-passant target, increment clocks, flip turn, append move).
   - Outcome: pure, testable state transitions; no mutation.
8. Create `src/lib/chess/moves.ts`: pseudo-legal move generation per piece type — sliding (b/r/q) with ray blocking, knight/king offsets, pawn pushes (single/double from start rank), pawn captures incl. en passant, castling (king-side/queen-side: rights intact, squares empty and not attacked, king not in check).
   - Outcome: candidate move list per square ignoring own-king safety.
9. Create `src/lib/chess/rules.ts`: `isSquareAttacked(state, sq, byColor)`; `isInCheck(state, color)`; `legalMoves(state, square?)` — filters pseudo-legal moves by simulating `applyMove` and rejecting any that leave own king attacked; `getGameStatus(state)` — checkmate (in check + no legal moves), stalemate (not in check + no legal moves), draw (50-move rule and/or insufficient material K vs K / K+minor vs K), else `check` or `playing`.
   - Outcome: fully legal move generation and correct game-end detection.
10. Create `src/lib/chess/notation.ts`: `toSan(state, move)` producing standard algebraic notation — piece letter (pawns omitted), capture `x`, destination square, promotion suffix `=Q`, castling as `O-O` / `O-O-O`, pawn-capture file prefix, piece disambiguation (file/rank when two same-type pieces can reach the destination), trailing `+` / `#` computed by applying the move and checking the resulting status.
    - Outcome: history entries like `e4`, `Nf3`, `exd5`, `O-O`, `Qxf7#` are correct.
11. Create `src/lib/chess/ai.ts`: `chooseAiMove(state)` for Black — enumerate all legal moves, score each: capture value by piece weight (p=1, n/b=3, r=5, q=9) minus small risk penalty, bonus for giving check, large bonus for checkmate, small random jitter; return the highest-scoring move (ties broken randomly). Keep it synchronous and fast (depth-1 heuristic; no external engine).
    - Outcome: AI plays plausible moves instantly, prefers captures/checks, occasionally varies.

## 4. Game state hook

12. Create `src/hooks/useChessGame.ts`: holds `GameState`, selected square, and cached legal moves for the selection; exposes `selectSquare(sq)` (select own White piece → show its legal destinations; clicking a highlighted destination applies the move; clicking elsewhere reselects/deselects), `newGame()` (reset via `initialState()`), plus derived `status`, `historySans`, `lastMove`. After every White move that leaves Black to move, schedule the AI reply with a short delay (~400–600 ms `setTimeout`, cleaned up on unmount/reset) so the Black move feels deliberate; ignore user input while it is Black's turn or the game is over.
    - Outcome: single hook orchestrates turns, AI replies automatically, restart works.

## 5. UI components (src/components/)

13. Create `src/components/ChessPiece.tsx`: renders a piece as a Unicode glyph (♙♘♗♖♕♚ set — use filled glyphs for both colors, differentiated with white fill + dark stroke for White and near-black fill for Black via CSS `text-shadow`/`-webkit-text-stroke`), sized responsively to the square, non-selectable, pointer-events disabled.
    - Outcome: pieces read clearly on both light and dark squares.
14. Create `src/components/ChessBoard.tsx`: 8×8 CSS grid with a thick wooden frame (`bg-wood-frame`, rounded, shadow); each square alternates `bg-wood-light` / `bg-wood-dark`, shows rank/file coordinate labels on the edge squares, renders the occupying `ChessPiece`, and overlays: selected-square ring, legal-move dots (centered circle) or capture ring (corner/edge ring on enemy-occupied squares), last-move square tint, and a pulsing red highlight on the king square when in check. Click events call `selectSquare`. Board always oriented with White at the bottom.
    - Outcome: fully interactive board matching the wooden theme with all required highlights.
15. Create `src/components/MoveHistory.tsx`: side panel styled as parchment (`bg-parchment`, subtle border, serif-ish heading "Moves"); renders history as numbered rows `1. e4 e5` pairing White/Black SAN per full move; auto-scrolls to the latest move (ref + `scrollIntoView` on history change); empty state text when no moves.
    - Outcome: live-updating SAN move list.
16. Create `src/components/GameStatus.tsx`: shows current turn ("White to move" / "Black (AI) is thinking…"), and a prominent banner on game end — checkmate ("Checkmate — You win!" / "Checkmate — AI wins"), stalemate, or draw; plus a `New Game` button (wood-toned, hover state) wired to `newGame()`. Also shows a subtle "Check!" indicator while a king is in check mid-game.
    - Outcome: clear status messaging and working restart.

## 6. Route composition

17. Create `src/routes/index.tsx`: home route (`/`). Calls `useChessGame()`, lays out a centered responsive page — heading "Chess", board on the left, right column with `GameStatus` and `MoveHistory`, stacking vertically on small screens (`flex-col lg:flex-row`). Board clicks disabled when game over or AI turn (enforced by the hook; reflect via cursor style).
    - Outcome: complete playable game on the home page.

## 7. Verification

18. Run `npm install`, then `npm run build` to typecheck and bundle, and `npm run dev` to smoke-test: make an opening move as White, confirm AI replies, legal-move dots appear on selection, move history updates in SAN, illegal moves are rejected, and New Game resets the board. Verify checkmate/stalemate banners via a quick forced line if feasible.
    - Outcome: build passes with no TypeScript errors; all listed gameplay requirements function.
